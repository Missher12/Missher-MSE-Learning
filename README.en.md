# MSE Learning

DSH plugin for global standing corrections, evidence-linked failure lessons and daily consolidation. Current local candidate: **0.16.0-rc.5** (version/documentation sync only; runtime code is unchanged from the verified **0.16.0-rc.4**, historical). The actual installed host version is read from the host load info and the corresponding receipt.

Ordinary user corrections no longer require a remember keyword. Suspected corrections enter a bounded, source-bound extraction after the turn; concrete reusable rules persist and recall in later related sessions/projects. Negations and project limits are retained; one-off requests, questions and quoted logs are not automatically promoted. The status page shows saved, pending and ignored extraction results. This uses the existing learning model route and switches, not a model call for every message.

Explicit user corrections persist across sessions and projects, with project constraints retained. Two independent failures can produce a concrete unvalidated lesson. Related turns recall it again; attributed recurrence requests a material revision or retires an ineffective version. Daily consolidation runs while idle after local 23:00, with durable processing boundaries and catch-up.

The slim runtime preserves source model routes, a single background slot, bounded calls, durable pause and unknown-cost no-replay. It does not self-award validated status or enable paid evaluation. A successful JSON parsing check proves only that check; assistant success claims and arbitrary exit0 do not verify the full task.

Use Settings → Self-evolution to inspect memory, recurrence, checks, daily summaries and waits. Read-only views do not call models. Background reflection can incur model charges and preserves existing switches.

The new memory-v1.json imports legacy lessons-v1.json read-only; retain original state and package/config backups. Historical problems and spending remain in the original file. Old unvalidated candidates are not promoted by migration. Daily quota fields are ignored; the old evaluation/merge/renewal pipeline is outside the new package.

Layout: `rebuild/` holds the whole runtime closure, UI panel and test; `src/` keeps only its direct pure helpers; `adapters/dsh/usage.mjs` parses host usage; `scripts/` cover packing, the publication allowlist and package verification; `PUBLICATION.md`/`VALIDATION.md` carry the current publication and validation records. Superseded code, old docs and images stay in Git history only. See [migration and limits](docs/AUTONOMY_0.15.0.md). Relevant checks use node --test rebuild/rebuild.test.mjs and node scripts/verify-package.mjs. Offline fake-provider evidence is not proof of long-term live-model effectiveness.

As of rebuild.23 the settings entry is named "Self-evolution"; only the display name changed, with learning behavior unchanged. rebuild.24 only cleans the public work tree (superseded core, tests, docs and the Hermes adapter leave the tree but stay in Git history), syncs the packing-script assertions and adds the official DSH badge; the 18 runtime modules are byte-identical.

Historical 0.16.0-rc.3: adds bounded, host-attributed prior-turn context (≤2 ended turns, ≤4 items, each ≤512, total ≤1536 UTF-16) used only to resolve references and project/temporary conditions; durability and scope are decided separately (durable methods may stay global, explicit project constraints stay scoped, durable+uncertain scope is kept as a readable project rule instead of being dropped, explicit temporary/one-off is refused), mixed messages are decided per correction, and a minimal decisions audit records why/where (current message or which prior turn) and the saved/ignored reason. Plugin/MSE-sourced text, tool output and outside-workspace material are excluded whole. 0.16.0-rc.2 keeps the rc.1 version-bound evidence and adds NATURAL-GATE-FIX: ordinary-correction admission reads REAL prohibition words through Node's built-in ICU word segmentation (Intl.Segmenter). The 别 inside 分别/区别/类别/识别/特别/别的/别人 is no longer a negation, and the SAME recognition is used for source and candidate. A positive clarification is an inversion only when it re-asserts the banned ACTION (拿…代替 / 重复运行…), not merely because it mentions the same object; real negations, object reversal and project/temporary scope stay strict. 0.16.0-rc.1 adds version-bound evidence and a bounded failure-method history. The learning store format is 4 (format 3 stays READ-compatible; the first real write migrates atomically). Each lesson keeps a current-edition window (injections / matched recurrences / check passes and fails, coverage `complete` or `since_upgrade`) separate from its family totals, and the old "3 family recurrences stop the lesson forever" rule is removed. A late checker or recurrence settles only the exact edition that was injected; a failed edition is recalled as a concrete guard warning, never as a recommended method. `methodHistory` is bounded to 128 rows of ≤6144 UTF-8 bytes each while the 2 MiB store bound is unchanged; revision prompts carry at most 6 related rows / 1536 bytes, a literally repeated mechanism is refused (`repeated_mechanism`), and a real replacement archives the old edition, resets the window and clears `evidenceHash` in the same transaction. A capacity pre-flight uses the ACTUAL archived row (128 rows / 2 MiB) before the model call, and REVIEW-FIX2 forecasts the whole start transaction (request/audit/ticket/format migration/archive/result increments from shared schema bounds) so a legal near-capacity store waits readably instead of throwing at beginWork. Tool/checker/JSON-selection feedback shares ONE receipt/offered attribution rule (cancelled terminal, guard, missing and partial editions are never credited; unknown historical counters only start since_upgrade). An edition freezes its OWN bounded source snapshot at birth/revision (multi-source sets are kept whole; overflow stays explicitly unknown) and an archived edition can only copy its old snapshot; the old method body must pass that edition's source+material admission before it is sent to a provider. Guards name a bounded, admitted concrete failure pattern without replaying old repair steps or inventing checker failures. Revision commits re-check the live parent and every archived FAILED edition with the same case-sensitive mechanism key, and history rows are re-admitted by their own frozen provenance plus the current source guard (withdrawn/unknown sources become fixed reasons only); partial legacy snapshots can never gain a complete window or a recovered method, a cancelled turn refuses late checker credit (keeping a voided de-duplication proof), guard wording states only observed facts, and a legal instruction is archived byte-for-byte. `scripts/replay-recall.mjs` plus `tests/fixtures/recall-cases.json` are a developer-only offline replay of 24 hand-labelled regression cases (not a blind test): zero model calls, no live-store access, no default-ranking change, and never part of the runtime package.
