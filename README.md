# MSE Learning

为 DSH 积累全局长期纠错与具体失败经验。当前版本 **0.15.0-rebuild.24**，是本地精简重建候选；发布与安装结果以交付记录为准。

## 工作方式

- 以“记住/以后”开头且无临时限制的直接规则即时保存；普通纠正结合前文提取具体规则，无需说“记住”。通用规则跨会话、跨项目召回，项目限制与否定词保留。
- 普通纠正在来源回合结束后空闲处理；仅疑似纠正进入有界模型提取，不给每轮聊天都新增调用。一次性要求、纯提问、引用和日志不会直接升级为长期规则，状态页可查看已保存、待处理及忽略原因。
- 两次独立同类失败触发复盘：使用有界脱敏诊断，产出原因判断、修复步骤和检查办法。根因推测不冒充已证实。
- 相关新回合再次带出经验，同回合去重；经验正文默认每轮最多 2 条、768 UTF-8 字节。
- 注入后的匹配失败进入复发与修订；没有实质变化不算新办法，持续无效的版本停用。
- 宿主本地时间 23:00 后空闲时做每日总结；无活动跳过，按持久处理边界补未处理事实。总结形成可召回经验。
- 可信来源回合的模型路线随请求绑定；一个后台在途槽，单次请求有界、费用未知不自动重放。暂停持久生效。

## 使用与状态

在 DSH 的 **设置 → 自我进化** 查看长期规则、经验版本、检查办法、注入/复发、最近每日总结及等待原因，并可暂停/恢复。只读查看不调用模型。

自动复盘/总结可能使用来源回合配置的模型并产生费用。保留既有 enabled/reflectionEnabled 开关；本版不提供自动付费评测或 validated 自授。普通 exit 0 和模型说“成功”不算客观验证；目前接入的确定性产物检查是项目 JSON 解析，其结论仅覆盖该检查。

## 升级与数据

安装前保留旧版本、配置与学习目录备份。新库为同目录的 memory-v1.json；旧 lessons-v1.json 只读导入，原始经验、问题和用量账本保留原文件。旧未验证方法不会凭升级成为可信全局方法。预算字段被忽略，复杂评测/候选合并/续期链已退出新运行路径。

## 0.15 采集与学习边界（新行为）

- **只采集宿主注册工作区内的会话**：归属由宿主 workspaceRegistry 判定，不是看 cwd 自称；注册表不可用或未登记的会话一律不采集（面板给出可读原因与安全计数，不含路径/正文）。
- **系统临时目录不是工作区**：即使被宿主登记（如「不在工作区」的 /private/tmp/… 临时分组），其根等于或位于系统临时目录（按 realpath 身份，含 /tmp↔/private/tmp 别名）时一律不采集、旧材料也不再发送；项目内部的临时文件不受影响（不看名字，只看根的真实身份）。面板显示有效许可数与「临时工作区未采集」计数。
- **临时要求不长期保存**：「这次别…」等任务内调整不会升级为全局规则；只有「记住/以后」开头且不含任务内限制的话术才即时入库，裸「别再/下次/纠正」进入有界候选队列，经证据核验后才可能成为规则。
- **正常纠正跨会话生效**：自然语言纠正经提取、审计后成为可召回经验，在项目工作区内跨会话注入。
- **明确纠正可修订旧规则且留档**：无条件、肯定的停用命令须绑定唯一旧规则及冻结版本；条件、否定、提问、引用和状态报告不构成停用授权。替换只在合格新规则同事务保存后退役旧版，空或无效提取保留旧版；原文与历史保留，面板显示版本、原因和时间。提问、引用或工单文本不会停用任何规则；引用歧义或目标已更新时整次变更零改动。
- **来源未知会少学**：无法证明在工作区内的路径引用（含旧队列里的历史材料）保守拒收、不再发送——宁缺毋滥是设计取舍；不含任何路径线索、无来源粘贴的外部正文无法可靠识别，属已知边界。
- **保留现有开关、路线与历史数据**：enabled/reflectionEnabled、模型路线绑定、memory-v1.json 及既有账本不变；旧库文件只读保留。

完整迁移与边界见 [0.15.0 说明](docs/AUTONOMY_0.15.0.md)。旧源码与历史文档、图片在 Git 历史与既往 Release 中追溯，工作树只保留当前精简运行闭包。它不训练模型权重，也不保证零错误。

## 仓库布局

- `rebuild/`：当前全部运行模块与 UI 面板及测试；`src/` 仅存其直接依赖的纯辅助模块；`adapters/dsh/usage.mjs` 宿主用量解析。
- `tests/fixtures/`：脱敏测试夹具；`scripts/`：打包、公开白名单与包验证；`docs/AUTONOMY_0.15.0.md`：0.15 迁移与边界。
- 根目录 `PUBLICATION.md`/`VALIDATION.md` 为当前发布与验证记录；私有证据、学习库与构建产物不在仓库。

## 历史迁移：rebuild.21

- 日总结按可证明的来源分批处理，每批最多64条；已处理事实按身份持久去重，暂时不可用的来源恢复后补做。缺少不可变来源的旧失败材料保留为“来源待确认”，不会借用新会话发送。
- 反思、修订与日总结采用4096 tokens单次输出上限；已知费用的截断或字段过长最多进行一次同材料压缩重试。固定30分钟复盘冷却退出当前路径，未知费用仍不自动重放。
- 日总结忠实链接现存有效纠正规则，保留项目、环境、否定和停用状态；新的失败方法包含具体原因假设、修复步骤与检查，进入同一未验证教训、召回、复发和版本修订链。普通任务摘要不会被提升为全局规则。
- 新来源、事实身份与诊断字段向后兼容；原开关、模型路线和23:00时间不变，旧学习库与账本保留。新格式写入后回退应先停用旧版本并保留完整新增库，不以旧快照覆盖新增事实。

本地安装与真实验收结论以交付记录为准。

## rebuild.22 迁移

- 失败复盘和修订会结合本回合的原生诊断报告，区分工具拒绝与进程内部错误；助手报告仍标记为未验证线索，不能代替真实检查。
- 诊断只收当前工作区、同会话同回合的原生助手文本，完整材料先检查权限与敏感内容，再保留最多512个 UTF-16 单位、1024个 UTF-8 字节的尾段。正常代码格式保留，外部临时材料和真正的权限指令仍拒收。
- 反思/修订的生成上限改为8192 tokens，为推理和正文留空间；最终教训仍不超过4096字节，具体指令不超过480字节。日总结4096、纠正提取1024→4096保持不变，来源模型和思考设置不改。
- 新诊断字段可选兼容旧库；无诊断时不改变旧材料身份，未知费用和已耗尽的材料不会因升级重新调用。真实新增证据才进入下一次学习。

rebuild.23 仅统一设置入口显示名为「自我进化」（英文 Self-evolution），不改学习开关、模型路线与汇总时点。

rebuild.24 只清理公开工作树：移除已退出运行路径的旧核心、旧测试、旧文档与 Hermes 适配（Git 历史保留），同步打包脚本断言并加官方 DSH 徽章；18 个运行模块字节不变。
